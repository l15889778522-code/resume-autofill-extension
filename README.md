# 简历投递助手

一个本地优先的 Chrome / Edge 浏览器扩展。它扫描当前页面的表单结构，通过本地规则或用户配置的 AI Agent 将网页字段映射到资料库，先展示预览清单，再由用户确认填写。

## 为什么第一版选择浏览器扩展

| 方案 | 优点 | 局限 | 结论 |
| --- | --- | --- | --- |
| Chrome / Edge 扩展 | 直接接触网页表单；安装轻；无需桌面权限；可人工确认 | 复杂自定义控件需逐站适配 | **第一版采用** |
| Windows exe + Playwright | 能控制完整浏览器流程；可做批量任务 | 登录态、验证码和风控复杂；维护成本高 | 适合后续半自动流程 |
| 剪贴板/悬浮窗 exe | 开发简单；网站兼容性高 | 仍需逐项点击粘贴，效率提升有限 | 可作保底工具 |
| 招聘网站专用脚本 | 单站效果最好 | 每个网站都要独立维护，页面改版容易失效 | 作为扩展的站点适配层 |

## 安装

1. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录 `resume-autofill-extension`。
5. 点击扩展图标，进入“资料库”录入信息并保存。

### 上传并解析现有简历

1. 打开扩展的“资料库”，点击“上传并解析简历”。
2. 选择 PDF、DOCX、TXT、Markdown 或 JSON 文件。
3. 在解析预览中检查识别结果；已有资料默认不覆盖，证件号码默认不选择。
4. 点击“应用所选并保存”。

教育经历和工作/实习经历都会按“最近到最早”保存为多段结构化记录。学校、专业、学历、日期和课程描述保持在同一条教育记录中，网页出现多组经历字段时会按相同索引成组填写，避免跨学校拼接。

文件和解析过程都留在本机浏览器内。普通文字型 PDF 可直接解析；扫描图片型 PDF 暂不带 OCR，需要先转成可搜索文字的 PDF。

## 使用

1. 打开招聘网站的简历编辑页。
2. 点击扩展图标，等待扫描。
3. 检查每个“网页字段 → 简历字段”的映射；错误时可在下拉框中修正。
4. 勾选要填写的项目，点击“填入所选字段”。
5. 回到页面人工检查；如果网站要求动态新增经历，请先在网页上建好对应数量的空区块，再由扩展逐组填写，最后自行提交。

### 使用 AI Agent 识别复杂字段

1. 打开“资料库 → AI Agent”，启用服务。
2. 填写 OpenAI Chat Completions 兼容接口、模型名称和 API Key；默认预置 DeepSeek 接口。
3. 保存时仅授权对应 API 域名。回到招聘页面，打开扩展并点击“AI 识别”。
4. Agent 会结合字段标签、所属区块、控件类型和选项生成映射建议；检查紫色 AI 置信度与理由后再填写。

Agent 只接收网页字段结构，以及“期望城市”“教育经历 1 · 专业”“工作经历 1 · 公司”等资料字段名称，不接收姓名、电话、邮箱、学校、专业、公司名称或经历正文。模型只能返回白名单中的字段引用，不能直接生成要填写的值；同一教育区块若引用了不同记录索引会被本地校验器直接丢弃。API Key 仅保存在本机扩展存储中，不会导出到资料备份或提交到代码仓库。

### 让插件学习简历外的问题

1. 遇到资料库没有的问题时，先在网页中手动填写。
2. 打开扩展，点击“学习本页填写”。
3. 预览插件准备保存的问题和值；敏感项默认不勾选。
4. 点击“保存所选答案”。下次出现相同字段时，它会进入自动填写预览。
5. 在“资料库 → 已学习答案”中可以随时修改或删除。

“院系”等标准经历字段会保存到对应的教育记录，而不是作为全局答案复用。插件会结合附近的学校、专业和日期判断记录；目标教育记录没有该值时会保持为空，等待你填写并学习，不会借用另一所学校的内容。

遇到只有一个“实习经历/实践经历”大文本框的网站时，插件会在本地把所有实习记录汇总为“时间｜公司｜职位 + 工作成果”的文本供你预览填写，不会让 AI 编造经历。

插件不会在后台监听键盘或静默采集页面；只有点击“学习本页填写”后才读取当前可见表单内容。

### 字段无法完全匹配时

- **高置信度（88% 及以上）**：自动选中，仍需点击“填入所选字段”。
- **中等置信度（68%–87%）**：展示建议映射，但默认不勾选，需人工确认。
- **低置信度或未知字段**：标记“待匹配”，通过下拉框手动选择资料或已学习答案。
- 手动修正后可记住本站映射；页面中新增的问题可通过“学习本页填写”保存。

未启用 Agent 时，近似匹配完全使用本地字符编辑距离和短语相似度。启用后也只有主动点击“AI 识别”才会发送经过脱敏的表单结构；接口失败会自动保留本地匹配结果。

## 隐私与安全边界

- 简历资料使用 `chrome.storage.local` 保存，不上传到开发者服务器。
- AI Agent 默认关闭；启用时只向用户配置的接口发送脱敏字段结构，不发送简历值。
- 扩展只在用户点击图标后获得当前标签页的临时访问权。
- 不读取或填写密码、文件上传框、隐藏字段。
- 身份证/证件号默认不勾选。
- 永远不点击提交、投递、发送或确认按钮。
- 卸载扩展会清除浏览器内的资料；可先导出 JSON 备份。

## 当前能力与限制

- 支持常见 `input`、`textarea`、`select`、单选框、`contenteditable` 和 ARIA `combobox` 字段。
- 支持在本地解析 PDF、DOCX、TXT、Markdown 和 JSON 简历，并预览后写入资料库。
- 会触发 `input` / `change` / `blur` 事件，以兼容多数 React/Vue 表单。
- 能记住同一域名下用户修正过的字段映射。
- 能在用户确认后学习简历外的额外问题，并在其他页面遇到相同字段时复用答案。
- 不会向招聘网站自动上传原简历，也不会点击“新增经历”；页面已经存在多组教育或工作经历字段时可按顺序逐组填写。
- 多段教育与工作经历已结构化保存；项目经历的结构化保存仍待支持。
- 可把多段结构化实习记录自动汇总到单个“实习经历”长文本框。
- 已支持常见 ARIA 自绘下拉框；跨域 iframe、封闭 Shadow DOM、级联日期/地区选择器仍可能需要站点适配器。

## 下一阶段建议

1. 增加项目和校园经历的结构化资料模型。
2. 为常用招聘网站增加独立适配器，覆盖级联日期、地区选择器和动态新增经历。
3. 增加多套求职画像（例如“数据分析版”“产品版”）和岗位 JD 关键词提示。
4. 加入本地投递记录，但仍保持最终提交由用户完成。

## 开发与测试

需要 Node.js 以及 Chrome、Edge 或 Playwright Chromium：

```bash
npm install
npx playwright install chromium
npm test
```
